RHEL Kernel Review Tools: Where mr-review Fits

Summary: revumatic is the officially recommended TUI for RHEL kernel MR reviews, with Kerneloscope integration, in-line commenting, and full GitLab workflow support. mr-review is an independent tool born from a specific reviewer's workflow preferences — particularly the use of external diff editors (vimdiff, meld) for patch-level comparison, batch conflict filtering, and mega-merge handling. It is not part of the official toolchain. This document places mr-review in context among the officially supported tools: revumatic, Kerneloscope, lab, rhstatus, and the GitLab WebUI.

Tool Overview

Patch Review   mr-review — Local Patch-Level Comparison

mr-review is a Python-based review tool that manages the complete MR review lifecycle: extracting patches from GitLab Merge Requests, formatting upstream counterparts, detecting differences, seeking missing fixes, presenting only the conflicts for human inspection, and taking action on the MR. It evolved from the long-standing patchreview bash tool, adding mega-merge handling, lore.kernel.org fallback, configurable prompts, and a rich terminal UI.

mr-review operates entirely locally — it needs only git, lab, and a diff editor. It does not use the GitLab API directly or require Kerneloscope access.

Typical usage:

cd /work/c10s/kernel && mr-review

or directly: mr-review mr 2816

mr-review Feature Detail

  • Smart batch comparison: All RHEL patches are compared against their upstream counterparts in batch. Patches that are identical to upstream are silently passed. Only patches with actual content differences (conflicts) are flagged for review, with possible false positives marked separately. This lets a reviewer focus on what matters.
  • Interactive diff viewer: Conflicts are presented one at a time in the user's preferred diff editor (vimdiff, meld, tkdiff, or emacs). Navigation keys allow replaying the last diff, going back one diff, jumping to a specific patch, substituting a different upstream commit, toggling conflict-only mode, and viewing missing fixes — all without leaving the viewer loop.
  • Missing Fixes: detection: For each upstream commit in the MR, mr-review searches upstream history (bounded by commit date for performance) for Fixes: tags referencing that commit. Any fixing commit not present in the MR series is flagged as a missing fix. Results are viewable from the diff viewer (f key) or as a standalone operation.
  • MR actions: After reviewing, the MR review menu offers: Approve, Approve with comment, Block (start a discussion), Unapprove (retract approval), and Comment only. The tool detects prior approval and warns before duplicating it.
  • Review history: Every MR action is recorded in a persistent history log with timestamp, action taken, patch count, and conflict count (e.g., Approved : 14 patches, 3 conflicts). Since conflicts require direct human inspection, the conflict count reflects the actual human effort expended on a review.
  • Mega-merge handling: When a single RHEL patch contains many upstream commits (e.g., DRM bulk merges with hundreds of commits), four strategies are offered: group by subsystem, filter by files touched, skip as bulk import, or paginated manual selection with search.
  • Upstream fallback chain: If an upstream commit is not found in the configured local tree, mr-review checks the RHEL patch's Upstream status: line. For lore.kernel.org URLs, it downloads the full mbox thread and matches patches by subject. For alternate git repo URLs, it temporarily fetches the commit from the remote.
  • Configurable prompts: Four review-flow prompts can be toggled on or off: ask before continuing, ask before replacing patches, ask before committing MR actions, and show comments in pager. If the user has already reviewed the MR, the continuation prompt appears regardless of config.
  • Kernel repo discovery: The W key scans the filesystem from / for kernel git repositories (directories with both .git and Kconfig), caches the results, and presents a selectable list for quick repo switching.

Patch Review   revumatic — Official Red Hat Review TUI

revumatic is the officially recommended terminal-based review tool for RHEL kernel development. It provides a full-screen TUI built around the GitLab API and integrates with Kerneloscope for commit tracking, missing-fixes detection, and upstream comparison. It supports in-line commenting on code, blocking threads, TODO list management, subsystem filtering, and side-by-side diff views — all within the terminal.

revumatic is maintained under the CentOS Stream kernel utilities and distributed via COPR. It uses pygit2 for git operations and speaks directly to the GitLab API rather than going through lab.

Typical usage:

revumatic   or   revumatic 2816

Backend Service   Kerneloscope — Commit Tracking Database

Kerneloscope is a Red Hat-internal service that indexes commits across all RHEL, CentOS Stream, and upstream kernel trees. It provides an RPC API for querying whether a commit has been backported, finding which trees contain a given commit, and identifying missing fixes. Both revumatic and the CKI webhook infrastructure query Kerneloscope to power their automated checks.

Kerneloscope is not a review tool itself — it is the data layer that other tools consume.

MR Management   lab — GitLab Command-Line Interface

lab is the standard CLI for interacting with GitLab — creating, listing, checking out, approving, and commenting on merge requests. It is the foundation that mr-review builds on for all MR operations. It does not perform patch comparison or upstream tracking.

Typical usage:

lab mr list origin --state opened --all

MR Management   rhstatus — Status Dashboard

rhstatus aggregates data from GitLab and Jira to provide a color-coded terminal report of a developer's TODO list, open merge requests, and their webhook-driven approval status. It is a monitoring tool, not a review tool.

Platform   GitLab WebUI — Web-Based Review

The GitLab web interface is the universal baseline. All MR operations — viewing diffs, commenting, approving, blocking — can be done through the browser. However, it shows only the RHEL-side changes and has no facility for comparing a RHEL patch against its upstream original.

mr-review sits outside the official toolchain. It uses lab for GitLab operations but is otherwise independent — a standalone tool for patch-level forensics built around external diff editors, batch conflict detection, and mega-merge strategies.

Why mr-review Exists

revumatic is the officially recommended and supported review tool for RHEL kernel development. Most reviewers should use it. mr-review is not a replacement or alternative — it is a personal tool that grew out of specific workflow preferences:

  • External diff editors: The author's review workflow relies on vimdiff and meld for patch inspection, with their full editor capabilities (syntax highlighting, folding, search, editing). mr-review extracts both RHEL and upstream patches as files and launches the preferred editor directly. revumatic provides a built-in side-by-side terminal view instead.
  • Conflict-first review: For MRs with many patches, the author prefers to batch-compare all patches first, then review only the conflicts. Patches identical to upstream are silently passed. mr-review was built around this workflow.
  • Mega-merge handling: The original patchreview bash tool could not handle MRs containing hundreds of upstream commits in a single patch (e.g., DRM bulk merges). This was the immediate trigger for rewriting the tool in Python with dedicated mega-merge strategies.
  • No Kerneloscope dependency: mr-review operates entirely from local git trees and the lab CLI. This was not a design goal so much as a consequence of the tool's lineage from the pre-Kerneloscope patchreview bash script.

revumatic provides significant capabilities that mr-review does not attempt: in-line code commenting, TODO list management, KABI analysis, Jira integration, Kerneloscope-powered cross-tree queries, and the full GitLab collaboration workflow. For the broader RHEL kernel developer community, revumatic is the right tool.
